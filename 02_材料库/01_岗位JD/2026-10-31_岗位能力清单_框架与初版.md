# 岗位能力清单（框架 + 初版）

> **来源**：公开校招信息与岗位要求的经验归纳（字节、腾讯、美团、银行科技岗等口径）
> **收集日期**：2026-10-31
> **置信度**：**中**。大厂 JD 页面多为 JS 动态渲染，无法直接抓取正文，本文件是归纳而非逐条引用。
> **必须做的一步**：按文末「采集手册」拉 20 份真实 JD 回来校准，把偏差改到这上面。
> **要回答的问题**：目标岗位要什么能力？我的项目该产出哪些证据？

## 一、五类岗位在要什么（校招口径）

| 能力项 | 后端 | 前端 | 算法 | 数据开发 | 测开/运维 |
|---|---|---|---|---|---|
| **主语言** | Java（最主流）/ Go / C++ | JS + TS | Python | Python + SQL | Python / Java / Shell |
| **数据结构与算法** | ★★★ 笔试必考 | ★★★ | ★★★ | ★★ | ★★ |
| **操作系统/网络** | ★★★ 八股主力 | ★★ 浏览器渲染、HTTP | ★ | ★ | ★★★ |
| **数据库** | ★★★ MySQL 索引/事务/锁 | ★ | ★ | ★★★ 数仓建模 | ★★ |
| **框架** | Spring Boot/Cloud、MyBatis | React 或 Vue + 工程化 | PyTorch | Hive/Spark/Flink | 自动化测试框架 |
| **中间件** | Redis、MQ（Kafka/RocketMQ） | —— | —— | —— | —— |
| **工程能力** | Git、Linux、Docker | Git、构建工具、性能优化 | Git、实验管理 | Git、调度 | Git、K8s、监控 |
| **项目权重** | **高** | **高** | **低**（看论文/竞赛/实习） | 中高 | 中 |
| **加分项** | 分布式、性能调优、开源 | Node/BFF、组件库、小程序 | 顶会论文、竞赛名次 | 指标体系、实时链路 | 自研工具、稳定性 |

### 三个直接结论

1. **后端岗位量最大、对项目要求最高。** 如果你岗位未定，后端的"能力迁移性"最好——学了后端，转测开、运维、数据开发都能用上一部分。
2. **算法岗不吃"工程项目"。** 投算法岗的话，做 Web 项目基本白费，要换成论文复现 + 竞赛。这就是为什么我反复确认你的岗位方向。
3. **所有岗位都考数据结构与算法。** 这条和项目并行，不能等。

## 二、通用必备（不分岗位，缺一项都扣分）

- 一门能写熟练的主语言（不是"学过"，是"写过几千行"）
- 数据结构与算法：能独立做出中等难度题
- 数据库：会写多表查询、知道索引为什么生效
- Git：分支、合并、解决冲突（不是只会 clone 和 push）
- Linux：会用命令行改配置、看日志、查进程
- **一个能讲清楚的项目**（这是本工作区存在的理由）

## 三、核心：能力 → 项目证据 映射表

> 这张表是全文件最有用的部分。**面试官不信"我熟悉 Redis"，只信"我遇到过缓存击穿，是这么解的"。**
> 做项目时，每完成一项就在"是否已有"打勾——打不满一半，说明项目深度不够。

| 岗位要求的能力 | 项目里必须产出的证据 | 是否已有 |
|---|---|---|
| 数据库设计 | 表结构设计文档 + 为什么这么拆表 + 一次真实的慢查询优化（前后耗时对比） | ⬜ |
| 索引与事务 | 你建了哪些索引、为什么、有没有踩过索引失效 | ⬜ |
| 缓存 | 用了 Redis 解决什么、缓存穿透/击穿/雪崩你遇到了哪个、怎么处理 | ⬜ |
| 并发控制 | 抢座位/报名/库存这类场景的锁设计；乐观锁 vs 悲观锁的取舍 | ⬜ |
| 接口设计 | RESTful 或 RPC 的接口清单 + 分页/鉴权/错误码规范 | ⬜ |
| 鉴权与安全 | 登录态方案（Session/JWT）、越权、SQL 注入防护 | ⬜ |
| 工程规范 | 目录结构、命名、代码风格、Code Review 记录 | ⬜ |
| 测试 | 单元测试覆盖率 + 一次线上 bug 的定位与复盘 | ⬜ |
| 部署运维 | Dockerfile + 部署脚本 + 域名/HTTPS + 日志 + 一次故障排查 | ⬜ |
| 性能 | 一个可量化的指标（QPS、响应时间、首屏时间），优化前后对比 | ⬜ |
| 前端工程 | 组件拆分、状态管理、路由、构建配置 | ⬜ |
| 数据/智能 | 检索或推荐效果的可量化评测（准确率/召回/成本） | ⬜ |

**用法**：项目第一阶段结束时，这张表至少打勾 6 项；第二阶段结束打到 9 项以上。打不满，就不算"能写进简历的项目"。

## 四、技术栈建议（三套方案）

| 方案 | 组合 | 优点 | 缺点 | 适合 |
|---|---|---|---|---|
| **稳（推荐）** | Java + Spring Boot + MySQL + Redis + Vue/React + Docker | 国内后端岗位量最大、校招资料最多、覆盖最广 | 重，上手慢（约 2–3 个月打底） | 岗位未定、想留最大选择面 |
| 快 | Node/Next.js 全栈 + Postgres + Vercel | 一周能上线，前端后端一套语言 | 后端深度弱，投大厂后端会被质疑 | 时间极紧、想先跑通闭环 |
| 潮 | Python/FastAPI + React + 向量库 + LLM | 契合 AI 应用方向，选题 B 必备 | 工程规范与并发能力体现弱 | 明确走 AI 应用/算法工程 |

**我的建议**：主选"稳"，但**先用 2 周做"快"方案的极简版跑通一次完整部署**（哪怕只是个能访问的页面），建立"我能上线东西"的信心和手感，再转"稳"。

理由：每周只有 5–10 小时，先用最小成本拿到"上线成功"的反馈，比一上来啃 Spring 生态更容易坚持。这是针对你时间碎片化的刻意设计。

## 五、附：2 小时采集 20 份真实 JD 的操作步骤

**为什么必须自己做**：JD 是动态网页，自动化抓取覆盖不全；而且"亲手读 20 份"的过程本身就是在建立岗位感，别人代劳会丢掉这个收益。

**准备**：一个表格（就用 `_JD采集表.csv` 的思路），列：公司 / 岗位 / 来源链接 / 硬性要求 / 加分项 / 我缺什么。

| 步骤 | 动作 | 耗时 |
|---|---|---|
| 1 | 打开牛客「职位」频道 + BOSS 直聘，搜"后端开发 校招/实习" | 10 min |
| 2 | 按公司挑：字节、腾讯、阿里、美团、快手、小红书、银行科技岗，各 2–3 个岗位 | 20 min |
| 3 | 每份 JD 只抄三样：**硬性技术要求**、**加分项**、**一句话岗位职责** | 60 min |
| 4 | 统计出现频次最高的 10 个技术词 | 20 min |
| 5 | 回到本文件，把"经验归纳"改成"JD 实证"，标出我说错的地方 | 10 min |

**验收标准**：能说出"投后端岗，JD 里出现最多的 5 个技术词是什么"，且能指出其中你目前会几个。

**注意**：BOSS 直聘上校招 JD 质量参差，优先用**公司官方校招官网**（字节/腾讯/阿里的 campus 页面）和**牛客职位库**。
