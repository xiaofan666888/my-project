# 数值原型（v0.1 之前的验证）

## 这是什么

一个**单文件网页**，只做一件事：验证"宠物多久会饿、心情怎么掉"这套数值好不好玩。

**没有后端，不联数据库，不需要装任何东西。** 双击 `pet.html` 就能玩。

## 怎么打开

双击 `D:\项目\prototype\pet.html`，会用默认浏览器打开。

手机上想试？把文件传到手机用浏览器打开也行（数值存在浏览器本地，不联网）。

## 你能验证三件事

| 验证项 | 怎么试 | 看什么 |
|---|---|---|
| **数值手感** | 点"快进 6 小时 / 1 天"，看三条进度条和宠物表情 | 掉得太快会焦虑，太慢会无聊 |
| **离线结算** | 关掉标签页，过几小时再打开 | 宠物应该按真实流逝的时间变饿，而不是停在原地 |
| **冷却** | 连点"喂食" | 按钮应进入倒计时，重复点无效 |

## 调参旋钮在哪

打开 `pet.html`，搜索 `const CONFIG`，就三块：

```js
decayPerHour: { hunger: 1.5, clean: 1, mood: 0.5, moodPenalty: 1.5, penaltyBelow: 30 }
initial:      { hunger: 80, clean: 80, mood: 70 }
actions:      { feed: {...}, bath: {...}, play: {...} }   // 各自的数值与冷却
```

改完刷新页面即可，**不需要重启任何东西**。

## 已经测过的曲线（当前参数）

```
时间      饱食  清洁  心情
  12h      62    68    64
  24h      44    56    58
  36h      26    44    48
  48h       8    32    24
  72h       0     8     0
```

读法：**一天不看，掉一半；两天不看，明显告急；三天不看，基本空了。**
这个节奏的目的是"让人想回来看看"，而不是"回来就被吓到卸载"。

## 这版改过两个地方

### 1. 参数从 3/2/1 调到 1.5/1/0.5

原来那组参数，模拟结果是 **24 小时心情归零、27 小时饿死**。一天不打开就病危，属于惩罚玩家。

### 2. 修了一个结算逻辑 bug

原来按"最终状态"决定要不要扣心情惩罚，等于把"饿了 3 小时"当成"饿了 3 天"。
现在改成**按小时分段结算**，惩罚只作用于真正低于阈值的那段时间。

> 这两条都是很好的面试素材："你怎么发现数值不对的？"——因为我写了个模拟跑了一遍，而不是凭感觉。

## 接下来你要做的

**玩两天，然后回答三个问题**（写进 `06_文档模板/03_踩坑记录.md` 或直接告诉我）：

1. 一天不打开，回来看到宠物很脏很饿，你是想赶紧照顾它，还是觉得烦？
2. 三个按钮的冷却（30/60/45 秒）是太短、太长，还是刚好？
3. 宠物除了"表情变化"，还需要什么反馈才觉得"它是活的"？

第 3 个问题很关键——**如果只是进度条在动，那它就不是宠物，是个仪表盘。**
